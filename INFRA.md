## Учётные записи приложения

Публичная регистрация **закрыта** (`disable_signup: true`), почта подтверждается
автоматически (`mailer_autoconfirm: true`), `site_url` — `https://pt.taylo.co`,
минимальная длина пароля 6 (меньше Supabase не разрешает).

Колодой пользуются `artem@taylo.co` и `yuliia@taylo.co` (заведены 28.10.2026).

**Как добавить человека.** Authentication → Users → Add user → Create new user,
обязательно с галочкой **Auto Confirm User**. Пароль придумывает владелец. При первом
входе клиент увидит, что подписок нет, и подпишет человека на все опубликованные колоды;
строк в `pt_cards` у него не будет, пока он не начнёт заниматься.

## Что заведено руками, а не кодом

Всё остальное поднимается миграциями из `supabase/migrations/`. Руками делается только то,
где нужны пароли и ключи:

1. **аккаунты людей** — Authentication → Add user + Auto Confirm;
2. **`OPENAI_API_KEY`** — Edge Functions → Secrets. Значение берётся на
   platform.openai.com → API keys → Create new secret key, показывается один раз.
   `OPENAI_MODEL` и `DAILY_LIMIT` необязательны (по умолчанию `gpt-4o-mini` и 300);
3. **DNS-запись** в GoDaddy и «Enforce HTTPS» в настройках Pages — один раз на домен;
4. **разрушающий SQL** по боевым таблицам (`delete`, `update … set deleted`) — выполняет
   владелец, предварительно сняв резервную таблицу.

Переменные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` функции выдаёт сама Supabase —
задавать их не нужно.

## Резервные копии

В приложении: **Настройки → Резервная копия → «Сохранить копию»**. Файл содержит прогресс,
настройки и список колод; **колоды в нём нет** — она общая и возвращается миграцией.

- кладите копию не только в папку загрузок: `…\portuguese\backups\` плюс любое облако;
- «Восстановить» читает такой файл обратно, сводя строки по времени правки: повторные
  вливания ничего не портят, порядок устройств не важен;
- «Отправить всё на сервер» нужна после восстановления: у строк старый `rev`, сервер их
  уже видел и сам ничего не спросит;
- раз в месяц — разумная частота. Бэкапов у Free-плана нет совсем.

**Прогресс второго человека возвращается так же и только на его устройствах.** Кеш лежит
под `user_id`, а не под именем, поэтому доставать его надо там, где человек занимался:
войти своей почтой → «Забрать из старого кеша» → «Отправить всё на сервер» → «Сохранить
копию». На каждом устройстве отдельно и до того, как в браузере что-нибудь почистят.

Чужой кеш при этом не попадёт: с 28.10.2026 кеш подписывается почтой владельца, и кнопка
пропускает чужие. Кеши, оставшиеся от прежних версий, подписи не имеют — такие вливаются
только после подтверждения, и на общем устройстве отвечать на этот вопрос «да» не нужно.

## Как поднять всё с нуля

Если проекта Supabase снова не станет, порядок такой.

**1. Новый проект.** Organization `taylo.co`, имя любое, регион Европа, пароль базы —
в менеджер паролей. Поле GitHub при создании пропустить: миграции заливаем сами.

**2. Миграции.** Полная история не нужна: 007–011, 014, 017–021 и 023–027 перекрыты
полными дампами колод 028–032. Порядок:

```
033 → 001 → 002 → 003 → 004 → 005 → 006 → 012 → 015 → 016 → 022 → 028 → 029 → 030 → 031 → 032
```

033 идёт первой: 001 переносит карточки из `pt_data`, и без этой таблицы перенос падает.
Как выполнять — в `CLAUDE.md`, раздел «Изменения в Supabase»: Management API из вкладки
с открытой панелью, SQL забирается с `raw.githubusercontent.com`.

Проверка после заливки: 6 колод, 4495 слов, `pt_cards` пуста, функции `pt_norm`,
`pt_cards_touch`, `pt_touch_updated`, `pt_bump_usage` на месте, RLS включена на всех `pt_*`.

**3. Функция `ai`.** Деплой multipart на `/functions/deploy?slug=ai` с `verify_jwt: true`
(рецепт там же). Без токена пользователя функция обязана отвечать 401 — это и есть проверка.

**4. Настройки входа.** `PATCH /v1/projects/<ref>/config/auth` с
`disable_signup: true`, `mailer_autoconfirm: true`, `site_url: https://pt.taylo.co`.
Новый проект по умолчанию открыт для регистрации — не забыть.

**5. Руками:** аккаунты людей и `OPENAI_API_KEY` (см. выше).

**6. Клиент.** В `index.html` поменять `SUPA_URL` и `SUPA_KEY` (ключ — Settings → API Keys,
вид `sb_publishable_…`; он публичный по замыслу), запушить, дождаться `built`
и сверить живой сайт с репозиторием.

**7. Прогресс.** На каждом устройстве: войти → «Забрать из старого кеша» или
«Восстановить» из файла → «Отправить всё на сервер». Числа сойдутся сами: слияние
берёт более свежую правку каждой карточки.

## Диагностика: симптом → причина

| Симптом | Где смотреть |
|---|---|
| «Load failed» при входе или добавлении слова | Жив ли домен проекта: `nslookup <ref>.supabase.co`. NXDOMAIN — проект спит (Free засыпает без запросов за неделю, будится Resume) или удалён. Либо браузер держит старую версию страницы — открыть с `?v=N` |
| Телефон показывает меньше слов, чем компьютер | Это нормально до конца синхронизации. Истина — на сервере; сверять `count(*)` и `count(*) filter (where archived)` в `pt_cards`, а не экраны |
| «Ждут отправки: N» не убывает | Читать **текст ошибки рядом**, а не число. «All object keys must match» — смешанная пачка (починено 28.10.2026); «Нет сети» — офлайн |
| Выученных стало меньше | Сравнить `count(*)` и `count(distinct pt_norm(word))`: дубли со старыми id заслоняют настоящие строки. См. «Грабли» в `CLAUDE.md` |
| Добавление слов не работает, остальное работает | Ключ OpenAI: есть ли `OPENAI_API_KEY` в секретах, не кончился ли кредит на счёте OpenAI (`insufficient_quota`) |
| 404 на новую таблицу после миграции | `notify pgrst, 'reload schema';` |
| `git push` отлетает с non-fast-forward | GitHub сам коммитит `CNAME` при переустановке домена — `git pull --rebase` |
